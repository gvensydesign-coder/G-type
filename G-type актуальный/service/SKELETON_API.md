# Движок «скелет + перо» — API для режима «Скелет»

Файлы: `core18.js` (движок), `core18c.js` (общий набор, регистрация, API правки), `core18a.js` (Линия), `core18b.js` (Пропись), `core18z.js` (альтернаты, кернинг, веса).

## Данные скелета
У каждого знака скелетного шрифта (`FONTS.liniya`, `FONTS.propis`) в `GL[ch]` есть:
- `skel(g)` — функция, возвращающая скелет для геометрии `g = makeG(safeP(p), w, h)`;
- `shape(g)` — контур = `skShape(skel(g), font, g.p)` (перо → `csgUnion` → `skSimplify`).

Скелет — массив штрихов:
```js
[{ nodes:[{x,y,a,b,w?,type,j?,cy?}], cap0, cap1, closed?, pen?, tl? },
 { dot:true, x, y, r }]                       // точка (круг)
```
- `x,y` — узел средней линии; `a`/`b` — абсолютные входящая/исходящая ручки (`null` — прямой отрезок к соседу).
- `type`: `'smooth'` (касательная непрерывна, G1) или `'corner'` (излом: штрих делится, стык — `j`).
- `j` (только излом): `'miter'` (острый, ограничение SKX.LIM), `'round'`, `'bevel'`; `cy` — срез выступа по горизонтали y=cy.
- `w` — нажим в узле (по умолчанию 1; между узлами — плавная интерполяция). У остроконечного пера масштабирует только нажимную часть (волосная остаётся), у эллиптического — всю ширину.
- `cap0`/`cap1` — окончания: `'R'` круглое (дуга пера), `'F'` плоское, `'H'`/`'V'` срез по горизонтали/вертикали через конец, `{cut:[dx,dy],at:[x,y]}`, `'X'` сужение, `'B'` шарик-капля, `'T'` — по параметру шрифта `term` (0 круг, 1 плоск., 2 срез, 3 капля), `'J'` стык (круглое, прячется в другом штрихе), `'C'` соединение прописи (плоское).
- `closed:true` — замкнутый штрих (овал): даёт внешний контур и просвет.

## Функции
```js
skelToContours(skel, pen, p)   // чистая функция: скелет -> контуры {hole,nodes} (без объединения)
skShape(skel, font, p)         // + skUnionChecked (csgUnion с проверкой, повтор со сдвигом, растровый запасной путь)
                               //   + skSimplify(tol = font.simpTol || 1.5): слияние сегментов, экстремумы сохраняются
skPenOf({kind:'ell'|'pt', ...}, p) // перо из параметров: ell — rx=stem/2, ry=hair/2, ang=nib; pt — hair, stem, press
FONTS[id].pen(p)               // перо шрифта
glyphSkeleton(ch, p, ed)       // {w, h, skel, pen} — скелет текущего шрифта с учётом правок ed.sk (для отрисовки)
skApplyEdits(skel, ed.sk)      // применить правки (чистая функция)
skPath(specs,{tens,closed})    // построитель: путь через точки (Хобби), spec=[x,y,угол°|null,{c,j,cy,w,di,do}]
skArcN(cx,cy,rx,ry,a0,a1)      // дуга эллипса (узлы на кратных 90°)
skXf(skel, fn) / skMirX(skel,w) / skReverse(stroke)
```

## Правки скелета (для режима «Скелет»)
Хранятся в правках знака: `S.edits[ch].sk`:
```js
{ 'si:ni': { p:[dx,dy], a:[dx,dy] | false, b:[dx,dy] | false, w:dw, type:'corner'|'smooth' },
  'si:cap0': 'R', 'si:cap1': 'F' }      // si — номер штриха, ni — номер узла
```
- Сдвиги ограничены ±`SK_EDIT_LIM` (160 ед.), нажим `w` — 0…2: архитектуру знака сломать нельзя.
- У гладкого узла при сдвиге одной ручки вторая остаётся на одной прямой (длина сохраняется).
- `buildBase` (обёртка в core18c) при наличии `ed.sk` строит контур из изменённого скелета, поэтому всё остальное
  (направляющие, сетка, наклон, поля, экспорт, Сверка) работает без изменений. Правки точек контура (`ed['ci:ni']`) применяются поверх.

Отрисовка в редакторе: `const r=glyphSkeleton(ch, cur().p, S.edits[ch])` → рисовать `r.skel` (кубические сегменты
`node.b → next.a`, точки — `dot`), перетаскивание узла пишет `S.edits[ch].sk[si+':'+ni].p`, затем пересчёт (`bump()`).
Наклон (`p.slant`) и поля добавляются после — скелет хранится в прямых координатах знака (0…w).

## Параметры (PARAMS, группа «Перо»; добавлены из core18c через PARAMS.push, у старых шрифтов скрыты)
`nib` угол пера −30…60°, `press` нажим 0…100 %, `term` окончания 0…3, `tens` натяжение кривых 0.8…1.3, `conn` связность 0…100 %.
Диапазоны дополнительно зажаты в `safeP` (обёртка).
Ширина знака растёт на nst·(stem−S0)·k, k = `font.wK` (Линия 0.55) или 0.85.
Пределы скелетных шрифтов — `FONTS[id].lim` (обёртка `paramLimits` в core18c): capH, xhR, ascA, desc, wdth, ov, stem,
stemK (stem ≤ stemK·xh), stemWK, hairR|hair, hairX, nibX (вертикальный размах пера ≤ nibX·xh), ascX, descX, nib, press, term, tens, conn, spur. Толщина пера — `stem` (вертикали/нажим), `hair` (горизонтали/волосная).

## Пропись: соединения
Строчные входят в (0, yc) и выходят в (w, yc), yc = 0.2·xh, угол 52° (до наклона), перекрытие 4 ед.;
поля шрифта `sb=0`, `opsp=0` (скрыты), поля прописных/знаков встроены в ширину. `conn<100` укорачивает хвосты (раздельное письмо).
Верхнее соединение (по канону: о в б ю я(вар.) o b v w): знаки с `topExit` выходят в (w, yh), yh = (xh−hy)·0.84.
Следующая строчная берёт вариант `<имя>.hi` (вход сверху) — GSUB `calt` (ChainContextSubst формат 3, `otChain3` в core15).
В превью приложения контекстной замены нет: `FONTS.propis.ctx(prev, ch)` возвращает имя нужного варианта
(`FONTS.propis.hiOf(ch)`, `FONTS.propis.topExit` — набор), режим «Скелет» может использовать это для показа пары.
Сверка: `FONTS[id].proof = {marginP, desc, descX, asc, noBar, stem, stemSet}` — подсказки для computeProof
(соединительные штрихи не считаются выходом за поля, законные выносные петли, ожидаемый ствол с учётом нажима).
Кернинг Прописи — только пары, где левый знак не соединяется (Т, V, P, F, O, L, Ь, знаки).

## Дополнения (этап 3)
- `SKX.FAST` (core18): быстрый режим — огибающая штриха ломаной по 10 точкам, `skShape` без объединения.
  Включается в `liveGlyphOf` (перетаскивание ползунка); результат не кешируется в CSG_CACHE.
- Превью: `ctxName(prev, ch)` (ui_a) — контекстный вариант знака (Пропись: `.hi` после о/в/б/ю/o/b/v/w),
  используется в `layout`, `layoutG` (сравнение, образец .png). Кернинг считается по исходным знакам.
- Превью скелетных шрифтов: незакешированные точные знаки сначала рисуются быстрыми, точные досчитываются
  порциями в простое (`gfSmart`/`refineStep`); профили классов кернинга превью — по быстрым знакам.
- Хуки шрифта: `ogX(b)(K,sk)`, `ogLow(K,sk)`, `ogI(K,sk)` — огонек по скелету базы; `pairOv(c,a,b,ov)`, `pairHi(a)`,
  `withHi(fn)` — диграфы œ љ њ соединяются как в письме; `simpTol`, `wK`.
- `skCompose(..., {keepBase:1, w})`: база строится в своей ширине, добавка ширины — справа (ď ť).
- Знак с `opt.tailL` (j ј Линии): оптическое левое поле по краю выше базовой, хвост — под предыдущую букву;
  Сверка: `proof.tailL`.
- Пропись: связность < 100 % укорачивает вход/выход по хорде к соседнему узлу (`isEnt`/`isExt` в `K.ent()/K.ext()`),
  очень короткий хвост отбрасывается.
