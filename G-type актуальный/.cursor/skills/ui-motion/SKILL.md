# UI Motion — профессиональная анимация интерфейса

Основа — покадровый разбор двух референсов пользователя:
- **V1**: мобильный таб-бар со стеклянной линзой и кнопкой «+», которая морфится в сетку инструментов (60 fps).
- **V2**: лендинг финтеха — прелоадер, подъём героя, пословное появление текста, мега-меню, кнопка → лоадер → успех, каскад карточек, счётчик (30 fps).

Дополнено правилами Stageshow (Benji Taylor, MIT; github.com/benjitaylor/skills) — §14–15; правило пользователя «ничего не выходит за края кадра/карточки» важнее любых правил Stageshow про кровотечение. §16 — постер шрифта (G-type). §17 — слайдер демо-карточек и сетка отступов демо (G-type, согласовано пользователем).

Пометки: **[M]** измерено по кадрам (±1 кадр), **[F]** подобранная кривая, **[D]** обобщение, в видео не показано, **[S]** правило Stageshow, **[U]** правило, согласованное пользователем.

## 0. Порядок работы (всегда)
1. **Бриф движения**: для каждого взаимодействия одна фраза — что сообщает анимация (причина→следствие, откуда пришёл элемент, смена состояния, внимание). Нет смысла — нет анимации.
2. **Раскадровка**: этапы по порядку, у каждого 1–2 свойства, якорь (точка, из которой растёт/куда уходит), длительность, кривая, задержка/каскад. Отдельно — обратный ход (закрытие) и прерывание.
3. **Токены**: только из шкал ниже (§2–3), без «магических» чисел в компонентах.
4. **Реализация**: CSS transitions/keyframes → WAAPI (`el.animate`) для последовательностей и прерывания → пружина (§5) для интерактивных морфов → FLIP (§7) для смены раскладки.
5. **Проверка**: запись экрана + покадровый замер (§12), QA-чек-лист (§11), reduced-motion, 4× замедление CPU.
6. Если есть референс-видео — сначала разобрать его по кадрам (§12) и записать таблицу замеров, потом строить.

## 1. Принципы
1. **Смысл.** Каждое движение отвечает на вопрос «что произошло и откуда».
2. **Пространственная непрерывность.** Элемент растёт из своего триггера и уходит в него. В V1 панель вырастает из «+», в V2 меню растёт из пункта навигации. Якорь неподвижен: кнопка в V2 ни разу не сдвигается.
3. **Иерархия.** Сначала контейнер, через 60–130 мс содержимое, потом детали. Следующий этап стартует, когда предыдущий прошёл 40–60 % [M].
4. **Асимметрия.** Появление медленное, с торможением (ease-out). Исчезновение занимает 45–60 % от появления, с разгоном (ease-in), без перелёта [M]: открытие V1 ≈730 мс, закрытие ≈280 мс.
5. **Физика.** Маленькие интерактивные морфы — пружина (перелёт ~3 %, ζ≈0.7). Хореография страниц и секций — сильные тормозящие кривые Безье.
6. **Отклик на нажатие.** Быстрая атака 70–115 мс, медленный отпуск 130–600 мс. Действие запускается на пике нажатия, не после отпускания [M].
7. **Прерываемость.** Любую анимацию можно развернуть из текущего состояния без скачка. Ввод во время морфа не блокируется (V1).
8. **Сдержанность.** Сложную смену состояния делать последовательными этапами по одному свойству, а не всем сразу (кнопка V2: форма → лоадер → цвет → форма → текст).
9. **Размытие** — короткий сигнал «материализации» (≈8–12 px, 70–130 мс), не постоянный эффект.
10. **Ничего не возникает рывком** [S]. У всего есть вход; элемент остаётся смонтированным, пока не закончится его выход. Пустых кадров при замене нет: новое приходит, пока старое уходит.
11. **Меняется только то, что изменилось** [S]. Анимируется изменившаяся часть текста или числа, остальное стоит; соседи сдвигаются на измеренную ширину.
12. **Отклик интерфейса — со скоростью продукта** [S]; замедляется только «рассказ» (демо, онбординг, презентация).

## 2. Шкала длительностей
| Токен | мс | Где применяется |
|---|---|---|
| `--dur-instant` | 80–100 | атака нажатия, подсветка плитки, смена иконки |
| `--dur-fast` | 150–230 | скольжение линзы вкладок (~230), мелкие фейды, hover |
| `--dur-base` | 280–370 | закрытие/сворачивание (~280), закрытие меню (~370), смена цвета (~330) |
| `--dur-slow` | 450–700 | морф формы кнопки (430–500), подъём карточек (600–700) |
| `--dur-expressive` | 800–1200 | подъём героя/секции (1100–1200), хвост раскрытия меню (~830), счётчик (~1000) |
| `--stagger-tight` | 30–45 | слова абзаца, печать символов (35–45 на знак) |
| `--stagger-base` | 90–130 | слова заголовка, строки, колонки меню |
| `--stagger-wide` | 140–250 | карточки, заголовки h2 |

Правило: суммарный каскад группы ≤ ~600 мс. При большом N шаг уменьшается. Stageshow [S]: внутри сцены 40–80 мс по порядку чтения (по умолчанию 60), между плитками сетки 80–120 мс.

## 3. Кривые и пружины
- `--ease-out: cubic-bezier(.2,0,0,1)` — подъём героя, секций и карточек, счётчик. Лучшее совпадение в V2: 80 % пути за первые 35 % времени [F].
- `--ease-std: cubic-bezier(.4,0,.2,1)` — меню, общий случай.
- `--ease-inout: cubic-bezier(.65,0,.35,1)` — любой морф формы (пилюля ↔ круг) [F].
- `--ease-in: cubic-bezier(.4,0,1,1)` — уход, закрытие, уезжающая секция.
- `--ease-out-soft: cubic-bezier(0,0,.2,1)` — отпуск после нажатия.
- `--ease-travel: cubic-bezier(.45,0,.1,1)` [S] — перемещение объекта из точки в точку в демо: мягкий старт, ясный путь, мягкое прибытие.
- `--ease-arrive: cubic-bezier(.25,.8,.25,1)` [S] — появление «из ниоткуда» в демо, 0,8–1 с.
- `linear` — вращение лоадера, кроссфейд цвета, шиммер.
- **Пружина `spring-panel`**: stiffness 240, damping 22, mass 1 (ζ≈0.72, перелёт 3–4 %, пик ≈250 мс, успокоение ≈500 мс). Это морф V1, допустимый диапазон 190–290 / 20–24 [F].
- **Пружина `spring-snappy`** [D]: 400 / 30 — переключатели, маленькие чипы.
- **Пружина `spring-gentle`** [D]: 120 / 18 — большие листы и шторки.
- Длительность и кривую выбирать вместе по задаче [S]; одна кривая на всё сплющивает иерархию. Переход между далёкими оттенками — ~200 мс (всё равно проходит через «грязь»), медленную часть несёт подпись.

## 4. Токены (вставлять в дизайн-систему)
```css
:root{
  --dur-instant:90ms; --dur-fast:180ms; --dur-base:300ms; --dur-slow:550ms; --dur-expressive:1000ms;
  --stagger-tight:35ms; --stagger-base:100ms; --stagger-wide:180ms;
  --ease-out:cubic-bezier(.2,0,0,1); --ease-std:cubic-bezier(.4,0,.2,1);
  --ease-inout:cubic-bezier(.65,0,.35,1); --ease-in:cubic-bezier(.4,0,1,1);
  --ease-out-soft:cubic-bezier(0,0,.2,1);
  --ease-travel:cubic-bezier(.45,0,.1,1); --ease-arrive:cubic-bezier(.25,.8,.25,1);
  /* CSS-пружина ≈ spring-panel через linear(); пересчитать solver'ом §5 при смене параметров */
  --ease-spring:linear(0,.18 6%,.52 14%,.83 24%,1.02 36%,1.035 42%,1.01 56%,.998 70%,1);
}
@media (prefers-reduced-motion:reduce){
  :root{--dur-fast:1ms;--dur-base:1ms;--dur-slow:1ms;--dur-expressive:1ms;--stagger-tight:0ms;--stagger-base:0ms;--stagger-wide:0ms}
}
```
При reduced-motion оставлять `--dur-instant` для цвета и прозрачности, а сдвиги, масштаб и размытие убирать через отдельные правила (§10).

## 5. Пружина (vanilla JS, прерываемая)
```js
function spring({stiffness=240,damping=22,mass=1,from=0,to=1,v0=0,onUpdate,onDone}){
  let x=from,v=v0,last=performance.now(),raf;
  const step=now=>{
    const dt=Math.min((now-last)/1000,1/30); last=now;
    for(let i=0,h=dt/4;i<4;i++){const a=(-stiffness*(x-to)-damping*v)/mass; v+=a*h; x+=v*h;}
    onUpdate(x);
    if(Math.abs(v)<1e-3&&Math.abs(x-to)<5e-4){onUpdate(to);onDone&&onDone();return;}
    raf=requestAnimationFrame(step);
  };
  raf=requestAnimationFrame(step);
  return {stop(){cancelAnimationFrame(raf)},get x(){return x},get v(){return v}};
}
// Прерывание: s.stop(); spring({...,from:s.x,v0:s.v,to:newTarget})
// Генерация CSS linear(): прогнать solver с фиксированным dt, взять ~20 точек x(t)
```
Эквиваленты: Framer Motion `{type:'spring',stiffness:240,damping:22}`, GSAP `power4.out` ≈ `--ease-out`.

## 6. Рецепты

### 6.1 Нажатие кнопки (V1)
- **Круглая плавающая кнопка**: `scale` до 1.08–1.3 и осветление заливки за 80–115 мс, удержание ~50 мс, возврат за ~130 мс. Иконка параллельно поворачивается на 45° (+ → ×) [M].
- **Прямоугольная кнопка** [D]: `scale(.97)` вниз, затемнение на 1 шаг, атака 80 мс, отпуск 200–300 мс.
- **Плитка в сетке**: яркость вверх за 70–90 мс, затухание по экспоненте 300–600 мс, масштаб ≈1.05. Без ripple [M].
- Действие срабатывает на пике (pointerdown + ~1 кадр), не на pointerup.
- Залитая кнопка под указателем остаётся своего цвета — на шаг темнее, без подмены на серый [S]. Результат меняет состояние после завершения нажатия.
```css
.btn{transition:transform var(--dur-base) var(--ease-out-soft),background-color var(--dur-base)}
.btn:active{transform:scale(.97);background:var(--c-press);transition-duration:var(--dur-instant)}
```

### 6.2 Hover [D]
- Вход 100–150 мс, выход 200–300 мс.
- Меню по hover открывать с задержкой 60–100 мс, иначе мерцает.
- У ссылок нет подложки при hover; у контрола подложка видна и в покое [S]. Подложки наведения и выбора — со внутренним отступом и скруглением.

### 6.3 Переключатель / чекбокс [D]
- Ползунок: `translateX` за 180–220 мс с `--ease-std` или `spring-snappy`.
- Дорожка: смена цвета 150–200 мс linear.
- Посередине хода ползунок может вытягиваться в ширину на ~1.1.

### 6.4 Вкладки и индикатор выбора (V1)
Один общий индикатор для всех вкладок, он переезжает, а не гаснет и не появляется заново. Этапы:
1. Приподнимается в «линзу»: scale ~1.1–1.25, ободок или тень.
2. Едет ~120 мс.
3. Сплющивается обратно.

Всего ≈230 мс, ease-in-out. Цвет иконки меняется по прибытии. Переезд делать через FLIP (§7). При переназначении цели на ходу индикатор сохраняет инерцию и едет к новой цели от текущей точки [S], а не стартует заново. Индикатор держать смонтированным: при перерисовке кнопок через innerHTML он теряется — переподключать.

### 6.5 Морф «триггер → панель» (V1, эталон)
**Открытие** (≈730 мс до полной остановки):
1. Содержимое триггера гаснет и размывается, ~50 мс.
2. Иконка триггера + → ×, кнопка возвращается в исходный масштаб.
3. Из точки триггера появляется размытый «призрак» панели (blur 8–12 px).
4. Панель растёт вверх-влево от якоря с `spring-panel`: перелёт +3 % к высоте на ~250 мс, затем успокоение ~320 мс без второго колебания.
5. Содержимое резкое уже на середине роста, через 70–130 мс после начала.
6. Внутренние плитки не каскадируются: движется контейнер.

**Закрытие** (≈280 мс, без пружины):
1. Схлопывание к якорю ~100 мс с `--ease-in`, содержимое сразу размывается.
2. Раскрытие в исходную форму ~165 мс с `--ease-out`, иконки становятся резкими.

**Прерывание**: разворот из текущего состояния с сохранением скорости.

Объект сохраняет идентичность при смене [S]: «+» становится «×» поворотом тех же штрихов, а не заменой иконки.

### 6.6 Выпадающее / мега-меню (V2)
- **Открытие**: ширина почти сразу до целевой (~50 мс), затем высота через `clip-path` от верхнего левого угла: 50 % к 180 мс, 90 % к 330 мс, хвост до ~830 мс (`--ease-out`). Колонки содержимого каскадом по 100–130 мс.
- **Закрытие**: ~370 мс, почти линейно с лёгким разгоном, без хвоста.
- **Малые поповеры** [D]: fade + сдвиг 4–8 px, 150 мс открытие, 100 мс закрытие.
- **Якорь** [S]: открытая поверхность (поповер, меню, палитра, шторка) прибита к краю, от которого открылась, и не «плывёт», когда меняется её содержимое; высоту резервировать под самый длинный список. Попап получает размер и прокрутку до первого кадра — не подстраивается во время открытия.
- Закрывается там, где был: хранить `{open, at}` раздельно, а не обнуляемую точку.
- Триггер с открытым поповером держит нажатый вид (`data-open`).

### 6.7 Аккордеон, раскрытие блока, height:auto [D]
- `grid-template-rows: 0fr → 1fr`, 300 мс `--ease-std`, содержимое fade через 60 мс.
- Закрытие 200 мс `--ease-in`, содержимое гаснет сразу.
- Для сложной раскладки — FLIP (§7).
- Стрелка-шеврон поворачивается за то же время.
- Движущийся край не режет текст [S]: содержимое гаснет до движения высоты и появляется после, либо маска только на движущемся слоте. Новая строка везёт за собой строки ниже (анимируется контейнер), а не появляется поверх.

### 6.8 Выезжающая панель / шторка / модалка [D, на основе асимметрии]
- Открытие: сдвиг от края ~450 мс `--ease-out` (или `spring-gentle`), подложка-затемнение fade 200 мс, содержимое через ~80 мс.
- Закрытие: ~250 мс `--ease-in`.
- Соседний контент, который раздвигается, двигать через FLIP теми же таймингами.
- Фокус переводится внутрь после открытия.
- Панель приходит уже с содержимым [S]: никогда не пустая поверхность на четверть секунды.

### 6.9 Появление элементов и каскад списков (V2)
- Элементы поднимаются снизу: `translateY(24–60px) → 0` + `opacity`, 600–700 мс `--ease-out`.
- Каскад 120–250 мс между карточками, всего ≤600 мс.
- Сначала оболочка, через 100–130 мс её содержимое.
- Порядок задаётся по смыслу: центральная или главная карточка может идти первой.
- Запуск по `IntersectionObserver` (порог ~15 %), один раз.
- Карточки, тосты, чипы приходят целиком чуть сверху [S], а не открываются жёстким краем; обрезать маской можно только строки текста. Сплошные объекты (окна, карточки, телефоны) приходят движением и непрозрачными — полупрозрачная карточка выглядит призраком.
```css
.rise{opacity:0;transform:translateY(40px)}
.rise.in{opacity:1;transform:none;transition:transform 650ms var(--ease-out) calc(var(--i)*var(--stagger-wide)),opacity 400ms linear calc(var(--i)*var(--stagger-wide))}
```

### 6.10 Исчезновение
- Вдвое быстрее появления, с `--ease-in`.
- `visibility:hidden` или удаление из DOM только по `transitionend` / `animation.finished`.
- Группа уходит обратным каскадом 40–80 мс [S], всё в пределах полсекунды; не всё разом.

### 6.11 Пословное появление текста (V2)
- Слово выезжает вверх внутри обрезанной строки, параллельно цвет серый → основной и лёгкое размытие → резкость.
- Каскад: дисплейный текст ~90 мс, h2 ~200 мс, абзац 30–40 мс. Одно слово 250–330 мс.
- Логотип раскрывается маской снизу вверх ~500 мс.
```css
.ln{display:inline-block;overflow:hidden;vertical-align:top}
.w{display:inline-block;transform:translateY(100%);opacity:.3;animation:wrd 300ms var(--ease-out) calc(var(--i)*90ms) forwards}
@keyframes wrd{to{transform:none;opacity:1}}
```
Доступность: исходный текст в `aria-label`, разбитые span — `aria-hidden`.

### 6.12 Кнопка → загрузка → успех/ошибка (V2, эталон)
Кнопка стоит на месте, этапы идут строго последовательно:
1. Задержка ~200 мс после клика (можно сократить до 0–80).
2. Пилюля схлопывается в круг (диаметр = высота кнопки), ~430–450 мс `--ease-inout`. Подпись обрезается `overflow`, не масштабируется.
3. Лоадер: в круге 3 точки по орбите, linear, ~1 оборот за 0.8 с. Крутится до ответа сервера.
4. Цвет перетекает (чёрный → мятный успеха) ~330 мс linear, точки гаснут.
5. Круг раскрывается в пилюлю ~500 мс `--ease-inout`. Текст результата печатается по 35 мс на знак.
6. Удержание ~300 мс, затем следующий шаг интерфейса.
- **Ошибка** [D]: та же схема с красной пилюлей, горизонтальная тряска ±4 px 3 раза за ~300 мс, затем возврат к исходной кнопке через 1.5–2 с.
- **reduced-motion**: этапы сменяются кроссфейдом без изменения формы.
- **Состояния в одном слоте** [S]: кнопка остаётся смонтированной, все варианты подписи лежат в одной ячейке grid, ширину заранее решить — держать по самому длинному варианту или анимировать ширину. Проверять самый короткий, самый длинный и «ожидание».
- Ошибка показывается на поле, которое её вызвало, и снимается исправлением поля; кнопка подтверждает успех на себе.
- **Читаемость успеха** [U]: состояние «Готово» должно читаться в обеих темах (контраст ≥ 4.5:1). Нет проверенного токена успеха — нейтральная пилюля (ink/surface) с иконкой ✓, а не бледный тёмно-зелёный.

### 6.13 Загрузка: скелетон, прогресс, спиннер
- Спиннер — по V2 (§6.12, п.3). Спиннер начинает вращаться до того, как становится видимым, и крутится, пока гаснет [S].
- **Скелетон** [D]: блоки повторяют будущую раскладку, шиммер-градиент 1.2–1.5 с linear. Замена на контент — кроссфейд 200 мс, контент каскадом 30–60 мс. Полоски скелетона стоят в той же строке, что заменяемый текст (тот же шаг строк), строки проявляются сверху вниз [S].
- **Прогресс** [D]: при неизвестной длительности `--ease-out` до ~90 %, по ответу довести до 100 % за 200 мс, затем fade.
- **Прелоадер страницы** (V2): знак раскрывается маской ~500 мс, затем открывается сцена.
- Показывать индикатор только если ожидание больше ~300 мс, иначе мерцает.

### 6.14 Смена чисел, счётчики (V2)
- ~1.0 с с сильным ease-out, `font-variant-numeric:tabular-nums`, цифры меняются на месте.
- Для живых данных — пружина к новому значению. `aria-live="polite"` с итоговым значением.
- **Прокрутка разрядов** [S]: меняются только изменившиеся цифры, последняя цифра первой, остальные стоят; без размытия от покадровой интерполяции; число получает свой слот; итог держится. Значение, прижатое к правому краю, меняется от этого края; иконка статуса рядом в фиксированном слоте. Знак валюты висит слева вне центровки — центруются цифры.
- Зависимое значение (итог, счётчик) меняется на такт позже своей причины.

### 6.15 Уведомление-тост [D]
- Подъём + fade ~300 мс `--ease-out`, висит ~3 с (пауза при наведении), уход ~200 мс `--ease-in`.
- Остальные тосты сдвигаются FLIP.
- Пока открыт диалог или шторка, тост не ложится поверх них: сообщение пишется в строку статуса самого диалога.
- Тост и разовые плашки никогда не перекрывают элементы управления [U]: место считается от всех плавающих панелей и доков (с отступом-токеном) и пересчитывается при ресайзе и при появлении панели (в т.ч. через 1–2 кадра после открытия экрана).

### 6.16 Переходы страниц и секций (V2)
- Уход: старая секция уезжает с разгоном (`--ease-in`, 450–600 мс), шапка получает полосу backdrop-blur.
- Вход: новая поднимается с `--ease-out` (карточки 600–700, полноэкранные блоки до 1100 мс), затем текст.
- Перекрытие 0–100 мс.
- Для SPA — View Transitions API (`document.startViewTransition`) с теми же токенами.
- Смена версий/вариантов — морф на месте или кроссфейд с плавной высотой подложки, без вспышки [S].

### 6.17 Перетаскивание и свайп [D]
- Во время жеста элемент следует за пальцем 1:1 без сглаживания.
- При отпускании скорость жеста передаётся в пружину (`v0`).
- За краем — «резинка» с сопротивлением 0.3–0.5.
- Порог срабатывания: 30–40 % пути или скорость больше 0.5 px/мс.
- [S] Подхват по ручке с сохранённым смещением захвата (элемент не «прыгает» центром под палец); при подъёме — тень и лёгкий масштаб; остальные расступаются непрерывно; отпущенный элемент садится в измеренный слот. Выделение текста — ровно под I-курсором.

### 6.18 Переход «карточка → детальный экран» [D]
- Общий элемент через FLIP или View Transitions, ~400 мс `--ease-out`.
- Остальной контент: fade 150 мс на уход, 250 мс на вход с задержкой 100 мс.
- [S] Объект, растущий в полёте, — мягкий старт и длинное торможение (≥600 мс); ease-in-out дёргает. Концы полёта фиксируются при старте. Вид меняется на конечный в последней трети полёта, не в кадре посадки. После посадки ничего не дёргается: размер, место и вид в кадре подмены совпадают; мерить сам элемент, а не обёртку с паддингами.

## 7. FLIP (смена раскладки без пересчёта кадров)
```js
function flip(el,mutate,{dur=300,easing='cubic-bezier(.2,0,0,1)'}={}){
  const a=el.getBoundingClientRect(); mutate(); const b=el.getBoundingClientRect();
  return el.animate([{transform:`translate(${a.left-b.left}px,${a.top-b.top}px) scale(${a.width/b.width},${a.height/b.height})`},{transform:'none'}],{duration:dur,easing,fill:'both'});
}
```
Масштаб контейнера искажает детей. Либо давать детям обратный масштаб, либо прятать содержимое на время морфа размытием или прозрачностью, как в V1. Поверхность, меняющая размер, никогда не растягивает свой текст [S]: размер, позиция и содержимое — одним переходом.

Чипы и списки, которые перерисовываются целиком: обёртка вида `keyed(box, keys, make)` — новые элементы проявляются ~300 мс, удалённые уходят «призраками» ~180 мс, оставшиеся едут FLIP.

## 8. Прерывание
- **CSS transitions** сами переходят к новой цели, но с полной длительностью. Для коротких переходов это нормально.
- **WAAPI**: `anim.commitStyles(); anim.cancel();` затем новая анимация от текущего состояния. Или `anim.reverse()` для обратного хода.
- **Пружины**: перезапуск с текущими `x` и `v` (§5).
- Не блокировать клики во время анимации. Состояние берётся из модели, а не из того, закончилась ли анимация.

## 9. Производительность
- Анимировать только `transform` и `opacity`.
- `filter:blur` и `backdrop-filter` допустимы коротко (≤200 мс) и на небольшой площади.
- `width`/`height`/`top` — только у маленьких элементов (кнопка V2). Для крупных — `clip-path`, `grid-template-rows` или scale с обратным масштабом.
- `will-change` ставить перед анимацией и снимать после; никогда на всю сцену — текст начинает мерцать [S].
- Сначала все чтения раскладки, потом все записи.
- Каскад делать одной CSS-переменной `--i`, а не таймером на каждый элемент.
- Скрытые вкладки и элементы вне экрана не анимировать.
- Проверять при 4× замедлении CPU: ни одного кадра дольше 16.6 мс на 60 fps.
- Иконка нечётного размера в чётном боксе «щёлкает» на полпикселя в конце движения [S] — чётные глифы в чётных боксах.
- Размер холста по ResizeObserver считать от `innerHeight`/размера контейнера, а не от собственного размера холста — иначе петля ResizeObserver.
- `overflow:clip` у ленты слайдера не даёт scrollIntoView прокручивать её, но устаревшая ширина ленты может дать мгновенный горизонтальный скролл страницы — контейнерам `min-width:0` и `minmax(0,1fr)`.

## 10. Доступность
- `prefers-reduced-motion: reduce`: убрать сдвиги, масштаб, размытие, параллакс и каскады; оставить fade/цвет ≤150 мс. Спиннер может крутиться, декоративные циклы останавливаются.
- Состояние никогда не передаётся только движением: в V2 успех меняет и текст, и цвет.
- Фокус виден всегда, в модалку переводится после открытия и возвращается к триггеру после закрытия.
- Не больше 3 вспышек в секунду.
- `aria-live` для статусов и счётчиков. При пословной анимации исходный текст остаётся читаемым.
- В демо-сцене при reduced-motion показывается постер (§14) — кадр с результатом.
- Живые демо инициализировать лениво (IntersectionObserver), играть только видимые, при скрытой вкладке и при отключённой анимации — стоп; `seek(t)` чистая функция времени, без id и без записи в DOM, если значение не изменилось (иначе MutationObserver/ResizeObserver зацикливаются).

## 12. Покадровый замер (разбор референса и проверка своей анимации)
1. **Запись**: компоненты 60 fps, страницы 30 fps. Для своей страницы — Playwright `recordVideo` или `page.screenshot` по кадрам с заморозкой времени.
2. **Кадры**: `ffmpeg -i rec.mp4 -vsync 0 f/%04d.png`. Обзорные листы: `ffmpeg -i rec.mp4 -vf "fps=6,scale=240:-1,tile=6x5" sheet%02d.png`.
3. **Сегментация**: средняя абсолютная разница соседних кадров (numpy). Участки выше порога 0.15–0.25 (по шкале 0–255) — отдельные движения. Длительность = кадры × 1000/fps.
4. **Трекинг свойства**: рамка порогового маски — размер и позиция; среднее значение участка — прозрачность и цвет; первая тёмная или светлая строка по столбцу — край.
5. **Подбор кривой**: нормировать прогресс 0–1, сравнить с банком cubic-bezier по RMSE; для пружины подобрать ζ и ω (перелёт % = exp(−ζπ/√(1−ζ²))·100).
6. **Допуски**: длительность и каскад ±1 кадр, перелёт ±1–2 п.п., форма кривой с RMSE < 1 % хода.
7. Учитывать дубли кадров: запись 60 fps может содержать источник 30 fps.
8. **Автодетекторы огрехов** [S] (по кадрам или по `getBoundingClientRect` в каждом кадре): «появилось, потом поехало» (элемент виден до начала движения), почти пустые кадры при замене, «сел на transform» (сдвиг 1–2 px между последним кадром движения и первым статичным), «шагает в боксе» (текст смещается внутри неподвижной рамки), смещение при передаче (handoff), дрейф якоря у поповера, текст ближе 8 px к краю карточки, края на расстоянии 1–3 px (почти касание), **выход за край кадра/карточки**. Найденное смотреть глазами: настоящее — чинить, намеренное — назвать; хорошее движение ради тишины детектора не вырезать.
9. **Раскадровка для согласования** [U]: 6 кадров в фиксированные моменты (анимация на паузе) одним листом, в обеих темах; финальные кадры показывают готовое состояние целиком.

## 14. Демо-сцены и иллюстрации интерфейса [S]
Для героя лендинга, карточек фич, онбординга, превью инструментов: миниатюра продукта, в которой происходит одно действие.

**Главная идея**: читается как настоящий продукт, упрощённый до нужного зрителю, кадрирован с намерением, у каждого движения есть причина.

Пять провалов: **перегруз** (настоящий текст в каждой строке), **вайрфрейм** (два серых прямоугольника и кнопка), **коробка** (окно целиком уменьшено в карточку с пустыми полями — лечится обрезкой окна по содержимому, а не уходом за край), **плоскость** (всё одного веса в одинаковых рамках), **пресность** (серое окно с курсором, хотя бриф просил характер).

**Порядок**: план до кода — место на странице, главный объект, действие, результат, что опустить. Размер под слот: ~720×340 герой рядом с текстом, 900–1100 во всю ширину, 400×300 карточка; не уже ~320. Для телефонной колонки — отдельная компактная раскладка (~358), а не сжатие.

**Сюжет**: форма по ценности продукта — «каково пользоваться» (жест и результат под рукой), «поток» (несколько экранов как один объект), «что делает система» (следствие появляется в другом месте, связь видна). 3–5 тактов и результат, петля 10–16 с. Открывается готовым экраном, который работает как стоп-кадр. Курсор между тактами отдыхает на пустом месте рядом со следующим действием; каждое его движение объяснимо; садится не на подпись.

**Постер** выбрать первым: кадр, который видят на превью, при reduced-motion и на скриншоте. Это такт, который рассказывает историю сам, никогда не середина изменения; результат остаётся на экране.

**Слова**: 3–7 настоящих строк (заголовок, объект действия, что набрано, результат), остальное — полоски-заглушки разной ширины (60/45/70/52 %). Полоски — по краям, не там, куда смотрит глаз. Одно большое число. Сохранять узнаваемый контент домена (обложки, аватары, превью букв).

**Кадрирование**: один главный объект и 1–2 спутника (спутник — второй объект другого рода, на хроме, не на контенте). Главный объект занимает ≥ 2/3 ширины. **Правило пользователя (важнее Stageshow): ничего не выходит за края своего кадра или карточки** — ни главный объект, ни спутник, ни текст, ни слово на обложке; никакого «ухода за край на 10–40 %». Окно демо обрезается по содержимому и целиком стоит в сцене с одним гаттером на все края (полный отступ; недолёт в 1–3 px — ошибка). Крупное слово/герой вписывать по реальному контуру букв (`actualBoundingBoxLeft/Right/Ascent/Descent`, максимум по всем весам/кадрам) внутрь паддинга; длинное — уменьшить до минимума, затем в две строки с зазором по чернилам ≥ 8 % кегля. Угловые элементы (вырез, кнопка-стрелка) не перекрывают буквы; бейджи сокращаются, если упираются в вырез. Нет мёртвых углов ни в покое, ни по ходу петли. Страница — это фон. Начинать плоско и фронтально.

**Проверка «внутри кадра»**: тест в каждом кадре петли (шаг 0.25 с) — `getBoundingClientRect` всех элементов внутри сцены с отступом ≥ 6 px, внутри героя ≥ 8 px, `scrollWidth ≤ clientWidth` у текста; для canvas — ink-box и окрашенные пиксели внутри паддинга на всех ширинах (400/768/1440) и обеих темах.

**Детали кадра**: текст от края карточки ≥ 12 px (флаг < 8); строка 12 px паддинг (8 в плотном списке); кнопка ≥ 8 px от поля над ней; подпись центрируется по буквам (`text-box: trim-both cap alphabetic`); вложенные формы: внешний радиус = внутренний + отступ; иконки из одного набора, одного размера и толщины, ≤ 14 px — заливные; никаких рисованных от руки значков и эмодзи вместо иконок; ни искорок/палочек/фиолетового для ИИ, ни придуманных логотипов «буква в квадрате»; герой не обводится кольцом с ореолом — выделяется поверхностью, тенью, акцентной подписью.

## 15. Петли и хореография демо [S]
- Сброс убирает добавленное одним целым и имеет видимую причину (отмена, закрыть, очистить) или невидим (снэп, пока скрыто). Навигация назад не проигрывается.
- Данные на глазах не откатываются: новое приходит как новое или откатывается за кадром.
- Результат держится ~2 с (не меньше 1.2–1.5 с [U]; готовое состояние не начинает гаснуть раньше общего сброса); ничего не стоит неподвижно дольше 3 с; через ≤ 1 с после выхода начинается следующее действие. Шов петли смотреть с шагом 60 мс.
- Связанные ответы перекрываются: изменённая настройка ведёт свою подпись, затем зависимые значения; подтверждение всё равно после причины.
- Накопительная история — конвейер: собранная пачка уходит, свежая появляется внутри кадра (не въезжает из-за края).
- Вторая сцена в петле оправдана, только если добавляет новое.
- Проверка: снять контакт-лист петли на реальной ширине и на 390 px, пройти каждое нажатие, меню, морф и шов; сначала чинить кадрирование, потом иерархию, потом движение, потом полировку. Свежий взгляд (агент, не видевший работу) отвечает: куда глаз попадает первым и результат ли это?

## 16. Анимированный постер шрифта (canvas)
- Чистый `seek(t)`, бесшовная петля 6–8 с, постер-кадр = момент с результатом (используется для PNG и reduced-motion).
- Смена насыщенности — по настоящей оси wght (переменный шрифт, собранный из глифов пользователя только с нужными знаками), а не кроссфейд двух начертаний (двоится). Нет оси — статичный кадр. Сборку кэшировать (последние 2–3), долгую — с прогрессом.
- Название вписывается по ink bounds (максимум по всем весам) в гаттер 24 px; длинное — до 64 px, затем две строки с зазором ≥ 8 % (на деле ~16 % читается лучше).
- Сетка знаков — без повторов: строчная, совпадающая по рисунку с прописной, считается повтором; добирать прописными, латиницей, цифрами.
- Выделение — скруглённый прямоугольник под глифом, глиф поверх инвертирован; смена подписи веса — кроссфейд, не «одометр» на сбросе.
- Экспорт: PNG 1080×1350, WebM через `captureStream` + `MediaRecorder` (vp9); нет MediaRecorder — кнопка неактивна с подсказкой. GIF не делать.
- Тосты и прочие слои не перекрывают открытый диалог/шторку.

## 17. Слайдер демо-карточек и сетка отступов демо (G-type) [U]
**Слайдер «Как это работает»** (для широких экранов, чтобы блоки не разъезжались):
- Число карточек по ширине: n = floor((W + gap) / (minW + gap)), ширина карточки = min(maxW, (W − (n−1)·gap)/n); сцена масштабируется целиком, ничего не обрезается. Все карточки помещаются — без автопрокрутки и управления.
- Бесконечная лента без клонов: карточка i в слоте (i − idx) mod N, сдвиг translateX; уходящая карточка переезжает за маской на другой конец, без перемотки назад. Шаг — WAAPI 550 мс (`--dur-slow`) `--ease-out`.
- Автопрокрутка каждые ~5.5 с; пауза при наведении, при фокусе клавиатуры (`:focus-visible`), после касания (~12 с), вне экрана (IntersectionObserver), на скрытой вкладке; при reduced-motion — только вручную и мгновенно.
- Управление: стрелки в шапке секции, точки (текущая — ink-пилюля), ←/→ на фокусе, свайп. ARIA: region + roledescription «карусель», слайды «N из M», скрытые слайды `aria-hidden` + `inert`. На телефоне — обычная лента со свайпом и fade по краю.
- Широкие мониторы: колонка главной ограничена токеном (`--home-max`, 1720 px) и центрирована; герой остаётся на всю ширину. Заголовок раздела выровнен по левому краю карточек, отступ заголовок → содержимое один токен во всех разделах.

**Сетка отступов внутри демо-сцены** (720×340):
- Окно приложения стоит на одном отступе от рамки карточки сверху, справа и снизу (`--dm-in`, 16 px сцены); плавающая плитка слева может заходить на окно, но целиком внутри карточки.
- Шапка окна — flex-строка высотой с угловую кнопку; кнопка в углу («Сбросить», «Очистить», «Создать шрифт»/«Готово») на равном отступе сверху и справа (`--dm-pad`, 20 px), заголовок по центру кнопки по вертикали.
- Зазор шапка → содержимое — один токен ≥ 8 px (`--dm-hgap`); не хватает места — уменьшается содержимое (холст, ячейки), а не отступ.
- Всё это проверяется автотестом на 6 ширинах в обеих темах по всему циклу анимации (±1 px).

**Один формат для всех демо (утверждено пользователем):**
- Никаких адаптивных/компактных вариантов демо-сцены: одна сцена 720×340, на любой ширине она масштабируется целиком (`transform: scale(W/720)`), иначе каждая правка делается по нескольку раз и баги живут в одном из вариантов.
- Все демо собраны из одного шаблона: окно приложения справа (одинаковые размер и позиция), шапка с заголовком и угловой кнопкой, одна плавающая плитка слева (одинаковый прямоугольник). Отличаются только содержимое и сценарий анимации. Автотест сверяет прямоугольники плитки и окна во всех демо (±1 px).
- Кнопка со сменой подписи («Создать шрифт» → «Готово»): подписи лежат в одной ячейке grid, ширина кнопки = самая длинная подпись, смена — кроссфейд, в каждый момент видна одна подпись. Состояние «Готово» — ink-пилюля с галочкой, а не цветная.
- Значение в плитке всегда с подписью, как в настоящем редакторе («Кернинг −70»), голое число непонятно.
- Цена масштабирования: на телефоне мелкий текст сцены ~6–7 px — допустимо, читается сама анимация; минимальная ширина карточки на десктопе ~440 px.

## 18. Уроки G-type v93–v95 (сообщения, избранное, загрузка, рабочие режимы) [U]

**Сердечко «в избранное».** Пружина иконки `--dur-base` (`spring-snappy`, лёгкий перелёт) + расходящееся кольцо `--dur-slow`, fade; только при добавлении, снятие — без эффекта. reduced-motion — мгновенная смена заливки.

**Сообщения и «Отменить».**
- Одна плашка-пилюля для info / успех / ошибка: что случилось (жирным), почему (серым), действие («Повторить» главное, «Отменить» второстепенное). Подъём + fade `--dur-base` `--ease-out`, уход `--dur-fast` `--ease-in`.
- Время жизни: обычное ~4 с (пауза при наведении и фокусе), ошибка ~12 с, с «Отменить» — пока не нажато действие или не ушёл экран.
- Место: никогда не поверх панели холста, дока, открытой нижней шторки, карточки при наведении. Позицию пересчитывать не только на resize, но и повторно через ~0.9 и ~1.7 с — панель могла открыться, пока сообщение висит.
- После любого обратимого действия (добавить/снять избранное, сброс параметров, удаление черновика) — сообщение с «Отменить» вместо диалога «Вы уверены?».
- В многошаговом режиме статус операции (обработка фото, сборка) — строкой внутри шага, а не тостом: тост внизу заставлял страницу прыгать.

**Загрузка.** Скелет повторяет будущую раскладку, шиммер linear 1.2–1.5 с, показывать только если ждём > ~300 мс; замена — кроссфейд 200 мс. Первый кадр обложки/холста проверяется: пустой кадр перерисовывается, пользователь не видит «пустую карточку».

**Живые демо и обложки вне экрана.** IntersectionObserver: анимация тикает только в видимой области и на видимом экране; скрытая секция и прокрученная за край демо не тикают (экономия CPU и батареи). Тест: счётчик тиков растёт на экране и стоит вне его.

**Подсказки в рабочих режимах.** Предпросмотр склейки штриха — тонкая метка в точке будущего стыка, появляется fade `--dur-fast`, без пульсации; тепловая карта подсвечивает только проблемы мягким пятном, спокойный текст без заливки (полосы-«маркеры» по всему тексту отвлекали).

**Пружинящий маятник у пустых состояний не нужен:** иллюстрация пустого состояния статична; движение только у действия.

**Проверка без видео.** Запись экрана для проверки движения пользователь не требует: проверять детерминированно — токены вместо литералов (грепом), длительность ухода < входа, reduced-motion выключает сдвиги/масштаб, тест тиков вне экрана, кадры в ключевых точках (`page.clock`/заморозка) — и всё это в обеих темах на 1440 и 390.
